Privacy, retention and deletion

Sovereign. Last updated 21 September 2026.

Sovereign is a self-hosted household budgeting application. One household runs one copy of it, on infrastructure that household rents in its own name. There is no company behind it, no account to sign up for, and nobody else's data in it.

What is stored, and who can read it

Everything Sovereign holds lives in a single document: accounts, transactions, budgets, rules, goals and settings. That document is encrypted in the browser with AES-GCM, under a key derived from a passphrase that is never transmitted. Only the encrypted result is uploaded.

The server cannot read the document. It is stored as ciphertext in a Postgres database and handed back as ciphertext. The hosting provider, the database provider and anyone with access to either see an opaque blob. Losing the passphrase means losing the data, because there is no recovery path and deliberately so.

What leaves the browser

  • The encrypted document, to the database, so the same household can open it on another device.
  • Requests to financial data providers, through this application's own server so that provider credentials never reach the browser. Plaid and SimpleFIN for accounts and transactions, Tiingo for security prices, RentCast for property valuations. Each receives only what its own request needs.
  • Questions asked of the assistant, to Anthropic, only when the assistant is used. It is given read-only access to answer the question asked and nothing is kept on the server afterwards. Not using the assistant sends nothing.

There is no analytics, no tracking, no advertising and no third-party script beyond Plaid Link, which is loaded from Plaid's own network only when a bank is being connected. Bank credentials are entered inside Plaid's dialog and never touch this application.

Credentials

Credentials that authorise every request, such as Plaid's client identifier and secret, are held in server environment variables and never sent to the browser. Credentials that belong to the household, such as a SimpleFIN access URL or a Plaid access token, live inside the encrypted document, which means they are unreadable to the server in the same way everything else is.

Retention

The document is kept for as long as the household keeps running Sovereign. It is not archived, copied to a second system, or retained after deletion. There are no backups held by anyone except the household, and any backup it exports is a file under its own control.

Nothing is retained server-side from a provider pull or an assistant question. The overnight job reads the document, writes it back, and keeps nothing of its own beyond a short queue of encrypted pulls waiting to be merged, which is emptied as soon as a browser opens them.

Deletion

  • An account or a transaction can be deleted inside the application at any time, and the change is written to the document immediately.
  • A bank connection can be disconnected in Settings. Its access token is handed back to the provider, so the provider stops holding it too.
  • Everything is deleted by deleting the row in the database, or by deleting the database. No copy survives it, and no request to anyone is required.

Because the data is encrypted end to end, deleting the passphrase is itself a deletion: what remains is ciphertext that nobody, including the people who run the infrastructure, can turn back into anything.
